Use the S.EE CLI to manage short URLs, text snippets, files, bio pages, and QR codes from your terminal.

- [sdotee/cli](https://github.com/sdotee/cli)
- [GitHub Releases](https://github.com/sdotee/cli/releases)

## Features

- **Short URLs**: Create, update, and delete links with custom slugs, domains, passwords, and expiration; view history and visit statistics
- **Text Snippets**: Share code and notes from stdin or files, with syntax highlighting
- **Files**: Upload files from paths or stdin, including private files and resumable uploads up to 5 GB
- **Bio Pages and QR Codes**: Create and manage bio pages and dynamic QR codes
- **Account**: Check API usage and validate API keys
- **JSON Output**: Add `--json` to any command for machine-readable output

## Installation

### macOS

```bash
brew tap sdotee/homebrew-tap
brew install see
```

### Debian / Ubuntu / RHEL (xTom repository)

[xTom](https://xtom.com/) packages the CLI in its [APT and DNF repository](https://github.com/xtomcom/repo) for `amd64` and `arm64`, so you get updates through `apt upgrade` or `dnf upgrade`. Supported systems: Debian 12 and 13, Ubuntu 22.04, 24.04 and 26.04 LTS, and RHEL, Rocky Linux and AlmaLinux 9 and 10.

Quick setup, which adds the repository for your system:

```bash
curl -sL ba.sh/repo | sudo bash
```

Then install the `see` package:

```bash
# Debian / Ubuntu
sudo apt install see

# RHEL / Rocky / AlmaLinux
sudo dnf install see
```

To add the repository by hand instead:

```bash
# Debian / Ubuntu
sudo apt install -y ca-certificates curl gnupg
curl -fsSL https://repo.xtom.com/xtom.key | sudo bash -c 'gpg --dearmor > /usr/share/keyrings/xtom.gpg'
echo "deb [signed-by=/usr/share/keyrings/xtom.gpg] https://repo.xtom.com/deb stable main" | sudo tee /etc/apt/sources.list.d/xtom.list
sudo apt update
sudo apt install see

# RHEL / Rocky / AlmaLinux
sudo curl -o /etc/yum.repos.d/xtom.repo https://repo.xtom.com/rpm/xtom.repo
sudo dnf install see
```

On Debian you can also run `sudo extrepo enable xtom` to add the repository. See the [xTom repository README](https://github.com/xtomcom/repo#usage) for more options.

### Linux packages

Every [release](https://github.com/sdotee/cli/releases) includes packages for `amd64` and `arm64`. Download the one for your system, then install it:

```bash
# Debian / Ubuntu
sudo dpkg -i see-cli_<version>_linux_<arch>.deb

# RHEL / Fedora
sudo rpm -i see-cli_<version>_linux_<arch>.rpm

# Alpine
sudo apk add --allow-untrusted see-cli_<version>_linux_<arch>.apk

# Arch Linux
sudo pacman -U see-cli_<version>_linux_<arch>.pkg.tar.zst
```

For example, `see-cli_1.4.0_linux_amd64.deb`.

### Arch Linux (AUR)

```bash
yay -S see-cli
# or the pre-built binary
yay -S see-cli-bin
```

### Pre-built binaries

[Releases](https://github.com/sdotee/cli/releases) also include archives for macOS, Linux, and FreeBSD (`see_<OS>_<arch>.tar.gz`) and for Windows (`see_Windows_<arch>.zip`), on `x86_64` and `arm64`. Extract the archive and put the `see` binary in your `PATH`.

### From source

Requires Go 1.26 or later:

```bash
git clone https://github.com/sdotee/cli.git
cd cli
make build   # builds ./see
```

## Configuration

Set your API key with an environment variable or a flag. Get your key from **[Tools > API Token](https://s.ee/user/developers/)**.

```bash
# Environment variable (recommended)
export SEE_API_KEY="your-api-key"

# Or use the flag
see --api-key "your-api-key" <command>
```

### Configuration Options

| Option | Environment Variable | Description |
|--------|---------------------|-------------|
| `--api-key` | `SEE_API_KEY` | Your S.EE API key (required) |
| `--base-url` | `SEE_BASE_URL` | Custom API base URL |
| `--timeout` | `SEE_TIMEOUT` | Request timeout. The flag takes a duration such as `30s`; the environment variable takes seconds |
| `--json` | - | Output JSON |

Run `see help <command>` for every flag of a command.

## Commands

### Domains & Tags

```bash
# Domains for short URLs
see domains

# Domains for text and files
see text domains
see file domains

# Your tags
see tags
```

### Short URLs

```bash
# Create a short URL (prints the short link)
see shorturl create https://example.com

# Create with options
see shorturl create https://example.com \
  --domain s.ee \
  --slug example \
  --title "Example" \
  --password secret \
  --expire-at 1798761600

# Change the target URL (--target-url is required)
see shorturl update example --domain s.ee --target-url https://example.com/new --title "New Title"

# Delete
see shorturl delete example --domain s.ee

# History and visit statistics
see shorturl history --page 1
see shorturl stats example --domain s.ee --period daily
```

`--domain` defaults to `s.ee`. `--expire-at` takes a Unix timestamp in seconds. Other create flags: `--tag-ids` and `--expiration-redirect-url`. The statistics period can be `daily`, `monthly`, or `totally`.

### Text Snippets

Text commands read from stdin, or from a file with `--file`.

```bash
# Create from stdin
echo "Hello World" | see text create --title "greeting"

# Create from a file
see text create --file ./snippet.txt --title "Code Snippet"

# Create with options
cat script.sh | see text create \
  --domain ba.sh \
  --slug demo \
  --title "Shell Script" \
  --type source_code \
  --password secret

# Update the content and title
see text update demo --domain ba.sh --file ./script.sh --title "Updated Title"

# Delete
see text delete demo --domain ba.sh

# History
see text history --page 1
```

`--type` can be `plain_text`, `source_code`, or `markdown`. `see text update` replaces the content, so it also needs `--file` or stdin.

### Files

```bash
# Upload one or more files
see file upload ./image.png ./document.pdf

# Upload with a domain and custom slug
see file upload ./document.pdf --domain fs.to --slug report

# Upload as a private file
see file upload ./invoice.pdf --private

# Upload from stdin (--name is required)
cat image.png | see file upload --name image.png

# History (30 files per page)
see file history --page 1

# Temporary download URL for a private file (valid for about an hour)
see file download-url <file-id>

# Delete with the delete key shown after upload
see file delete <delete-key>
```

Files up to 100 MB are uploaded in one request. Larger files are uploaded in resumable chunks, up to 5 GB. Stdin always uses a single request.

### Bio Pages

```bash
see bio create "My Bio" \
  --description "About me" \
  --mastodon-url https://c.im/@s.ee \
  --link Blog=https://example.com

see bio update <id> --title "Updated Bio" --link Blog=https://example.com
see bio history --page 1
see bio delete <id>
```

`--link title=url` can be repeated. Links passed to `update` replace the existing custom links. `create` also accepts `--domain`, `--slug`, and `--rss-url`.

### QR Codes

```bash
see qrcode create https://example.com --title "Example"
see qrcode history --page 1
see qrcode delete <slug> --domain s.ee
```

`--title` is required. Creating a QR code prints its short URL and the PNG, SVG, and PDF image URLs.

### Account

```bash
# API, content, file, and storage usage
see usage

# Check the configured API key, or another key
see token check
see token check <api-key>

# Version
see version
```

## JSON Output

Add `--json` to any command for machine-readable output:

```bash
see shorturl create https://example.com --json | jq -r '.short_url'
```

## Examples

### Create a short URL and copy it (macOS)

```bash
see shorturl create https://example.com | pbcopy
```

### Upload a screenshot and print its URL

```bash
see file upload ~/screenshot.png --json | jq -r '.url'
```

### Shorten every URL in a file

```bash
while read -r url; do
  see shorturl create "$url"
done < urls.txt
```
